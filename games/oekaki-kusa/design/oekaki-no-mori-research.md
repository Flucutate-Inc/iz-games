## 0. 要約(結論だけ読む人向け)

- **お絵かきの森の本体は「お絵かきクイズ」ではなく「広場(滞在できる場)」である。**
  ミニゲームは7種あるが、広場5種のうちミニゲームが主役なのは1種だけ。
  残りは自由おえかき・雑談・自作お題・配信・ソロ用。ゲームは滞在の口実にすぎない。
- **面白さの源は「絵の上手さ」ではなく「伝達の誤差」。** 7モードはすべて
  「お題 → 絵 → 解釈」の情報を"どう劣化させるか"のバリエーションとして設計されている。
  下手であることが芸になるので、画力差があっても同じ卓が成立する。
- **描いた絵が残り、他人の遊びの素材になる循環がある。**
  試合終了 → 推薦コーナー(他人が選んでコメント) → 投稿画面(公開するか本人が決める)
  → 公式ギャラリー「みんなのおえかき」 → **その絵が「おえかき検定」「はやおし検定」の問題になる**。
  この循環が **「人がいない時間帯」を過去のプレイヤーで埋める**構造になっている。
- **2024年の公式スマホアプリ「あつまれ！おえかきの森プラス」おひろめ版は、
  エゴコロクイズ単体に絞った結果、約3ヶ月(2024/3/14 → 2024/6/26)で終了した。**
  一方ブラウザ版は2010年から16年、**2026年8月現在も現役で更新が続いている**
  (直近アップデート 2026/8/6、メンテナンス予定 2026/8/26)。
  **「ゲームだけを移植すると死ぬ」というのが最大の教訓**である。
- スマホ化で物理的に壊れるのは主に **(A) ひらがなフリーテキストでの回答**、
  **(B) 横長4領域同時表示のレイアウト**、**(C) 1試合10〜20分のセッション長**、
  **(D) 6人同時集合の前提**。「草」の発明ポイントはここに集中する。

## 2. 場の構造 — 広場5種

導線は3ステップ: **STEP1 部屋を選ぶ → STEP2 おえかき・ミニゲーム → STEP3 投稿する**。
広場を選ぶ → ロビーを選ぶ(定員200人単位) → 部屋を作成 or 入室 or ランダム入室。
部屋にはパスワードで鍵をかけられる(友達だけの部屋)。

| 広場 | 用途 |
|---|---|
| なんでも広場 | ミニゲーム・おえかき・おしゃべり、なんでもみんなで楽しむ |
| おえかき広場 | ミニゲームで遊ばず自由におえかきしたいとき |
| じゆう広場 | **ミニゲームのお題を自分たちで自由に決められる**(ユーザー出題) |
| さつえい広場 | **動画・配信撮影する時に推奨**(部屋作成時に「撮影」マークを付ける) |
| おえかき検定 | 過去に他の人が描いた絵を選択肢から当てる **一人用**ゲーム |

> **設計上の含意**: 「ゲームをしない場所」が3つ、「一人で遊べる場所」が1つある。
> つまり **人が集まらなくても、ゲームをしたくなくても、居場所がある**。
> これが16年続いた構造的な理由と考えられる。

## 3. ミニゲーム7種 — 「劣化のさせ方」のカタログ

回答は全モード共通で **チャット欄に全角ひらがなのみ**で入力する。
公式FAQ曰く「ひらがな以外で答えを入力すると、答えが当たっていても不正解になる」
「なるべく略語などは使わずに正式名称での入力をおすすめします」。お手つきペナルティはない。

| モード | 人数 | 仕組み | 情報が壊れる場所 |
|---|---|---|---|
| **エゴコロクイズ** | 2名以上 | 1人が描き手、残りが回答者。お題を絵で伝える | 描き手の画力・発想 |
| **スピードおえかき** | 3名以上 | 複数の描き手が**極端に短い持ち時間で1枚をリレー描き足し**、1人が当てる。お題はエゴコロより易しめ | 時間の不足＋分業のズレ |
| **おえかきリレー** | 3名以上 | **お題を知るのは最初の描き手だけ**。以降は前の人の絵を見て、お題を推測しながら描き足す | 伝言による解釈の連鎖崩壊 |
| **めかくしおえかき** | 2名以上 | エゴコロと同じだが、**描き手に自分の描いた絵が見えない** | 描き手の自己制御(軌跡の記憶勝負) |
| **おえかき検定** | **1名以上** | **過去に他の人が投稿した絵**を、5つ程度の選択肢から当てる | (非同期・ソロ) |
| **はやおし検定** | 2名以上 | 同じアーカイブ問題を**早押しボタン**で競う。獲得ポイント最多が勝ち | (反射神経・競争) |
| **ぬりえ** | **1名以上** | 用意された線画を協同で色を塗る。クイズではない | (非競争・雑談の口実) |

> **設計上の含意**: 7種は「お絵かきクイズの派生」ではなく、**伝達経路のどこを壊すかの体系**である。
> 時間を削る(スピード)、視覚を奪う(めかくし)、経路を伸ばす(リレー)、
> 回答を選択肢に変える(検定)、競争軸を反射に変える(はやおし)、競争そのものを外す(ぬりえ)。
> 「草」でモードを選ぶときは、**この体系のどこを取るか**で考えるべき。

### 3.1 エゴコロクイズ(コアモード)の進行

- 部屋に入室 → 右下の **「GAME START」で準備完了** → **全員が準備完了になると自動開始**
  (もう一度押すとキャンセル)。2人以上から開始できる。
- 描き手はランダム選出。**「描き手拒否」設定で選ばれないようにできる**
  (絵に自信がない人が回答専門で居られる = 参加のハードルを下げる装置)。
- 難易度は **かんたん / ふつう / むずかしい / すべて**。
  易: 「海」「いちご牛乳」 / 難: 「教育番組」「歌舞伎」。
- **「早く答えることができれば高得点」**(残り時間に応じた配分)。**描き手にも得点が入る**。
- 誰かが正解する、または時間切れで次の描き手へ。**不正解のペナルティはない**。
- **全7枚**を描いた時点で終了、最高得点者が **MVP**。
- **4人以上のときは最後のお題を2〜3人で協力して描く**。正解時は全員にボーナス得点。
- 1枚あたりの制限時間は概ね60秒前後、長くて180秒(§10 の未確定事項を参照)。

## 4. 画面と道具

### 4.1 レイアウト(PC横長・4領域同時表示)

```
┌────────────────────────────────┬──────────────┐
│                                │ のこり◯枚     │
│                                │ のこり◯秒     │
│        キャンバス(最大領域)      │ 難易度        │
│                                ├──────────────┤
│                                │ チャットログ   │
│                                │ (入室/出題/   │
│                                │  回答/正解者が │
│                                │  色分けで流れる)│
├────────┬──────────────┬────────┤              │
│プレイヤー│ ペイントツール │        │ [GAME START] │
│カード×6 │ クレヨン/消しゴム│       │ 描き手拒否    │
│ アバター │ /透明度/太さ7段 │       │ ルール設定    │
│ 得点    │ /全消し/戻る進む│       │ 友だちと遊ぶ  │
│ 称号    │ /かおもじ/最小化│       │ 絵を投稿/保存 │
│ フォロー │               │        │ 退室         │
└────────┴──────────────┴────────┴──────────────┘
上部: 通報 / 設定 / 遊び方 / 音量
```

**この4領域同時表示が体験の核**である。「絵が育っていく様子」「回答が飛び交う様子」「誰が何点か」を
同時に見られるから、「あ、今の線で伝わった」「3人が違う方向に外している」という
**ズレの実況**が成立する。片方を隠すと面白さが落ちる。ここが縦画面移植の最大の難所(§8-B)。

### 4.2 ペイントツールの仕様

| 道具 | 仕様 |
|---|---|
| 基本クレヨン | 最初から使用可能。**減らない** |
| 特殊クレヨン | ゲーム中に獲得。**使うと残量が減り、0で使用不可**。同じ色を再獲得で全回復 |
| 消しゴム | 描いた線を消す |
| 透明度 | クレヨンの色の透明度を設定 |
| 線の太さ | **7段階** |
| 全消し | キャンバスを全消去 |
| 戻る / 進む | 1手分の undo / redo |
| かおもじスタンプ | 顔文字を貼る |
| 最小化 | ペイントツールを収納してキャンバスを広く使う |

**フリーハンドのみ。図形ツール・塗りつぶし・レイヤー・選択範囲は存在しない。** アプリ版の色数は13色。

> **設計上の含意**: この貧しさは手抜きではなく **平等装置**である。
> 道具で差がつかないから、勝負が「発想と手の速さ」に収束し、画力のある人が圧勝する競技にならない。
> **機能を足すと壊れる**タイプの設計。唯一の"強化"は色数だが、これは強さではなく表現の幅に効く。

### 4.3 特殊クレヨンの巧妙な循環(公式FAQより)

- 使用すると残量が減り、0になると使えない。
- **「一定量以上使用すると、ゲーム結果画面で同じ色のクレヨンを一定確率で獲得できる」**。
- つまり **使わないと補充されない**。温存はむしろ損。
  → 「もらった色を惜しんで使わない」を防ぎ、**表現を試させる**方向に働く報酬設計。

## 5. 育成と報酬(公式FAQより)

- 得点に応じて **スマイルポイント** を獲得 → **アイテムゲージ**が上昇 →
  「Next Item」として **新しいクレヨンが解放**される。
- クレヨンを**コンプリートするとアイテムゲージは上がらなくなり、獲得スマイルポイントも0Pointになる**。
  ただし **称号** と **絵本** は引き続き獲得できる。
- 称号は自己紹介欄に表示される肩書き。
- **レート・ランキングは存在しない。** これは「気軽に遊べる」理由としてレビューで明示的に評価されている。

## 6. 承認と保存のループ(最も見落とされやすい心臓部)

ミニゲームが終わると、**必ず2画面のシーケンスが挟まる**。

### 6.1 推薦コーナー(選択タイム 約106秒)

- 「今回みんなが描いたお気に入りの1枚を"みんなのおえかき"に推薦しよう！」
- 全員の絵がサムネイル一覧(描き手アバター＋お題つき)で並ぶ。
- **1枚を選び、80字以内のコメントを添えて「推薦する」**(例: 「どうしてこうなった!?」)。
- 「選ばないで戻る」も選べる。時間切れで自動的に部屋へ戻る。

### 6.2 投稿画面(選択タイム 約57秒)

- **「いただいたコメント」** = 推薦画面で他の人がくれたコメントが並ぶ。
  各コメントにチェックボックスがあり、**外したコメントは投稿されない**。
- 自分のコメントも添えられる(例: 「『トロッコ』を描いてみた。」)。
- 「ハンゲに投稿」 / 「ツイッターに投稿」 / 「投稿しない」の3択。
- 公式FAQ: 投稿すると **公式サイトの「みんなのおえかき」に反映**される。
  **1人1点だけ**投稿できる。**他人の絵を投稿するには作者の許可が必要**で、
  許可が得られなければ投稿できない。
- 別途「絵を保存」でローカル保存も可能。

### 6.3 この構造が生んでいるもの

1. **承認は他人経由でしか得られない。** 自分から「これを晒したい」とは言えない。
   誰かが選んでくれて初めて投稿画面が開く。→ 承認が"贈られたもの"になり重みを持つ。
2. **公開の最終決定権は本人にある。** 推薦されても投稿しない自由、他人の絵は許可がなければ出せない。
   下手な絵を勝手に晒される恐怖がないから、**安心して下手に描ける**。
3. **投稿された絵はアーカイブになり、おえかき検定/はやおし検定の問題になる。**
   → **UGCフライホイール**。今日のプレイヤーが、明日の一人プレイのコンテンツを作る。
   「オンライン小規模ゲームで人が集まらない」という最大の敵に対する構造的な解答である。

```
描く ──▶ 当てられる ──▶ 推薦される ──▶ 本人が公開を決める ──▶ みんなのおえかき
                                                                    │
        おえかき検定(1人用) / はやおし検定 の問題として再利用 ◀──────┘
```

## 7. 文化・秩序維持

- **OK部屋**: 描き手が「OK」と言うまで回答禁止。じっくり見てから当てる遊び方。
- **即答部屋**: 思いついた順に矢継ぎ早に回答を撃つ。
- **G / ｇ**: 「ググってきます」の意。
- **描き手拒否**: 回答専門で参加する権利。
- ヒントを出す、キャンバスに文字を書く等の"ズル"も、**面白ければアリ**という空気。
- **荒らし対策(公式FAQ)**: 「不適切な絵・発言」「描いている絵を削除して退室」等に対し、
  **部屋主のみが「追放」できる**(友だちと遊ぶ → 入退室タブ → 追放する)。
  追放すると入室が規制され、**「追放対象者の描いた絵や絵を消した情報は消失」= 荒らされた絵が修復される**。
  加えて画面右上の**通報ボタン**で運営に通報できる。
  > **技術的な含意**: 「特定ユーザーの描画だけを巻き戻せる」ということは、
  > キャンバスがビットマップではなく **作者IDつきのストローク列**として保持されている。
  > 「草」でも同じモデルを採るべき(追放・巻き戻し・リプレイ・差分同期がすべてこれで解ける)。

## 8. 本質の抽出 — 7つの命題

### 命題1: 商品は「絵」ではなく「伝達の誤差」である
お題 → 絵 → 解釈の各段で情報が劣化し、その劣化量が笑いの量になる。
7モードはすべて劣化のさせ方の変奏。**画力は面白さの必要条件ではなく、時に阻害要因**。

### 命題2: 得点は勝敗の道具ではなく「通じた度合いの計測器」
残り時間比例配分、描き手にも加点、誤答ペナルティなし、レートなし、ランキングなし、MVPは称号だけ。
競技ではなく**協調**。だから初心者が卓を壊さない。

### 命題3: 道具の貧しさが平等を生む
フリーハンドのみ・7段の太さ・13色。機能を足すと画力差が可視化され、平等が壊れる。
**制約は仕様であって、未実装ではない。**

### 命題4: ゲームは「場」の一機能にすぎない
広場5種のうちミニゲーム主役は1種。他は自由描き・雑談・自作お題・配信・ソロ。
**滞在できる場所が本体で、ミニゲームは滞在の口実。**
→ アプリ版がエゴコロクイズ単体に絞って3ヶ月で終わったのは、この主従を反転させたから。

### 命題5: 描いた絵が残り、他人の遊びの素材になる
推薦 → 投稿 → 検定の問題化。「描いて捨てる」を「描いて残る」に変える3段。
かつ検定は1人で遊べる = **過去のプレイヤーが現在の空席を埋める**。

### 命題6: 承認は他人経由でしか得られず、公開は本人が決める
自薦できない(重みが出る) / 拒否できる・他人の絵は許可制(安心して下手に描ける)。
この2つが同時に成立している点が巧み。

### 命題7: 観られることが前提に組み込まれている
「さつえい広場」を公式が用意している。卓 vs 観客の構図に拡張でき、
視聴者がお題を出し答えを叫ぶ遊びが成立する。72名規模の大会が回るのはこの延長線上。

## 9. スマホ化で壊れるもの(「草」が解くべき問題)

### 問題A: 回答が「ひらがなのフリーテキスト入力」である ★最大の難所
原作の即答性は「3人が同時に『やきゅう』『そふとぼーる』『きゅうぎ』を撃ち合う」ことで生まれる。
スマホでこれをやると、**フリック入力＋IME確定を、キーボードが画面の半分を占めた状態で、
残り時間と競って**行うことになる。物理的に再現できない。
しかも判定は**ひらがな厳格一致**で、公式FAQの筆頭が「ひらがな入力ができません」
「回答しても正解になりません」であることからも、PCですら摩擦点だったことが分かる。
- 解の方向: 音声入力 / 手書き入力 / 予測候補タップ / 選択肢化 / かな盤タップ /
  そもそも回答を「打つ」から「選ぶ・並べる」に変える。**ここが「草」最大の発明ポイント。**

### 問題B: 縦画面に4領域が入らない
キャンバス＋チャット＋得点＋ツールの同時視認が体験の核(§4.1)なのに、縦画面では2領域が限界。
しかも**キーボードが出ると更に半分失う**。
- 解の方向: 回答を「流れるチャットログ」から「キャンバス上に浮かんで消える吹き出し」へ /
  得点表示を最小化 / ツールを片手親指圏に集約 / キーボードを使わない(問題Aと連動)。

### 問題C: 1試合が長すぎる
7枚 × 60〜180秒 ＋ 推薦106秒 ＋ 投稿57秒 = **10〜20分超**。
(アプリ版は3問3〜5分に短縮していた。方向性としては正しい。)
- 解の方向: 3枚で1セット / 1枚30〜45秒 / 推薦と投稿を短縮または非同期化。

### 問題D: 6人同時が集まらない
スマホは起動タイミングがばらける。原作は「ロビーに常時人がいる」PC文化に支えられていた。
- 解の方向: **検定型(非同期・1人)を主軸に据える** / 2〜3人で成立する設計 /
  過去プレイヤーの絵を混ぜる。命題5がそのまま解になる。

### 問題E: 「場に滞在する」がスマホと相性が悪い
広場でだらだら滞在するのはPCブラウザ的な体験。スマホでは通知ベースの断続的接触になる。
- 解の方向: 滞在の代替として「非同期で積み上がる場」(投稿アーカイブ・他人の絵を当てに来る)
  を場の中心にする。命題4を"滞在"ではなく"再訪"で満たす。

### 問題F: 指で描くと線が汚い
ただしこれは**必ずしも問題ではない**。命題1・3より、下手さは資産。
本当の問題は「意図した線が引けないフラストレーション」であって、汚さそのものではない。
- 解の方向: 手ブレ補正は入れる。ただし画力を補うツール(図形・塗りつぶし)は入れない。

## 10. 「お絵かきの草」への移植方針(たたき台)

| 原作の要素 | 草での扱い | 根拠 |
|---|---|---|
| 伝達誤差の笑い | **守る** | 命題1 |
| フリーハンドのみ・道具の貧しさ | **守る**(手ブレ補正のみ追加) | 命題3 |
| 描き手にも加点 / 誤答ペナルティなし / レートなし | **守る** | 命題2 |
| 描き手拒否(回答専門で居られる) | **守る** | 参加ハードル |
| 推薦による他者承認＋本人の公開拒否権 | **守る** | 命題6 |
| 絵が残って検定の問題になる | **守る・むしろ主軸に昇格** | 命題5＋問題D |
| 使うと補充される特殊クレヨン | **守る**(表現を試させる報酬) | §4.3 |
| 作者IDつきストローク列でキャンバスを保持 | **守る**(追放・巻き戻し・同期の基盤) | §7 |
| 7枚フルセッション | **捨てる**(3枚程度に) | 問題C |
| 常時滞在型の広場5種 | **作り替える**(滞在 → 再訪) | 問題E |
| ひらがなチャット回答 | **作り替える(最重要の発明ポイント)** | 問題A |
| 横長4領域同時表示 | **作り替える** | 問題B |
| 6人同期前提 | **作り替える**(非同期主軸＋少人数同期) | 問題D |
| 配信対応(さつえい広場) | **後回しだが捨てない** | 命題7 |

### 命名について
「森 → 草」。小さい・軽い・すぐ生える。同時にネットスラングの「草」= 笑い。
**名前自体が「短いセッションで笑いを生む」というコンセプトを言っている。**
1セッションが短いこと、成果物が笑いであることを、そのまま設計指針にできる。

### 技術的な前提(このリポジトリの制約)
- リアルタイム対戦は静的バンドル(GitHub Pages)では配信できない。
  先例の [`games/wanwan/`](../../wanwan/) と同じ **Cloudflare Workers + Durable Objects** 構成を取る
  (無料枠で動く。同じ `server/src` が Node でも Workers でも動くよう `wrangler.jsonc` の alias で差し替えている)。
- IZ アプリとの連携は [`sdk/iz-sdk.js`](../../../sdk/iz-sdk.js) 経由。独自サーバーを持つ場合は
  `IZ.getIdToken()` で Firebase ID トークンを受け取り、**サーバー側で署名・aud・iss・exp を検証**する
  ([PROTOCOL.md](../../../PROTOCOL.md))。
- IZ を賭けるなら iz-app 側 `game-registry.ts` への登録 PR が必須。
  ただし本作は協調型なので、**賭けゲームにはしない**方が命題2と整合する。
  スコア送信(`IZ.submitScore`)やゲーム内通貨購入(`IZ.purchase`)の余地はある。
