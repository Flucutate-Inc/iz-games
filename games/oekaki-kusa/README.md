# お絵かきの草

『あつまれ！お絵かきの森』の**エゴコロクイズ**を、完全スマホ向けに作り直したもの。
1人が描き手になってお題を絵で伝え、残りが**ひらがな**で当てる。3枚で1試合、2〜6人。

原作の何を守り、何を作り替えたのかは [design/oekaki-no-mori-research.md](design/oekaki-no-mori-research.md)
（仕様調査と本質抽出）と [design/spec.md](design/spec.md)（実装仕様）を正とする。

- **サーバー権威型**: お題・正誤判定・得点・作品の保存はすべてサーバーが決める。
- **縦画面いっぱいがキャンバス**。回答は流れるチャットではなく、絵の上に浮かんで消える吹き出し。
- **描いた絵は全部ギャラリーに載る**。対戦の絵も、ひとりでかいた絵も、描いた時点で並ぶ。
- **いいね・コメント・シェア**: ギャラリーの絵にはいいね(トグル)とコメントが付けられ、
  シェアボタンで絵を PNG にして端末の共有シート(Web Share API)から送れる。
  シェアリンク(`/?drawing=<id>`)で開くと、その絵がすぐ表示される。
- **推薦コーナー**: 対戦の最後に、その試合で描かれた絵から1人1票で好きな絵を選んで
  コメントを添える。推薦は「その絵へのいいね+コメント」としてそのままギャラリーに残る。
- **ひとりでかく**: 対戦とは別に、1人でお題を描いてギャラリーに載せられる。
- **月間絵しりとり**: 月ごとに1本、みんなで繋ぐしりとり。リアルタイムに集まらなくても、
  誰かが最後に描いた絵を「なんだとおもう？」と**自分で予想して**繋げる。前の人の実際の
  ことばとの一致はチェックせず、ズレてもしりとりは続く（ズレそのものが面白さ）。
  ことばが明かされるのは次の人が繋いだとき。参加するとその月のしりとり全体
  （答え合わせ済みの絵+ことば+誰がどう読んだか）が見られる。
- **ホーム画面の背景**には、いままで描かれた絵がランダムにうっすら流れる。
- ゲームはサーバーを持つため **GitHub Pages では配信できない**。
  わんわん大戦争と同じく **Cloudflare Workers + Durable Objects**（無料枠で動く）に置く。

## 起動方法

```bash
cd games/oekaki-kusa
npm install
npm run dev
# → http://localhost:8788
```

`npm run dev` は毎回 `worker/build-assets.sh` を走らせてから wrangler を起動する。
**`public/` を直接編集したら `npm run assets` を忘れないこと**（wrangler が配信するのは
生成物の `worker/public/` なので、忘れると古い画面が出続ける）。

2人での動作確認は、同一 localStorage を避けるためにブラウザ2窓を別オリジンで開くのが手軽:
`http://localhost:8788` と `http://127.0.0.1:8788`。

## テスト

```bash
npm run dev          # 別の端末で起動しておく
npm test             # 2人分のクライアントを実際に繋いで1試合通す
```

「部屋に入れる → 全員準備で始まる → 描ける → ひらがなで当たる → 得点が入る（描き手にも）
→ 3枚で終わる → 推薦コーナーで投票する → 推薦がいいね+コメントとして絵に残る →
描かれた絵は全部ギャラリーに載る」を一本道で確認する。あわせて「ひとりでかいた絵も
そのまま載る」「いいねのトグル・コメント・単品取得(シェアリンク用)」も別のテストで確認する。

## デプロイ

```bash
npx wrangler login   # 対話端末で1回だけ
npm run deploy
```

デプロイ後の URL をリポジトリ直下の [`games.json`](../../games.json) に登録すると
IZ アプリのゲーム一覧に出る。

## ログイン

IZ アプリ内（WebView / iframe）で開かれた場合は、`sdk/iz-sdk.js` の `IZ.getIdToken()` で
Firebase ID トークンを受け取り、**サーバー側で署名・`aud`・`iss`・`exp` を検証**してから
セッションを発行する（[PROTOCOL.md](../../PROTOCOL.md)）。
`iz:init` の `user.uid` は表示用で偽装できるため、認証には使っていない。

IZ の外（普通のブラウザ）では、なまえだけのゲストログインで遊べる。こちらは IZ の
アカウントとは別枠で、IZ の残高には一切触れない。

> **このゲームは IZ を賭けない。** 得点は勝敗のためではなく「どれだけ通じたか」の目盛りで、
> レートもランキングも持たない（原作の設計をそのまま引き継いでいる）。
> そのため IZ アプリ側 `game-registry.ts` への賭けルール登録は不要。

## ルール

| 項目 | 値 |
|---|---|
| 人数 | 2〜6人 |
| 枚数 | 3枚（原作は7枚。スマホの1セッションに合わせて短縮した） |
| 制限時間 | 1枚 60秒 |
| 答え合わせ | 6秒 |
| 得点（回答者） | 20 + 80 × 残り時間の割合 |
| 得点（描き手） | 正解者1人につき 30 |
| 誤答 | ペナルティなし |
| 開始条件 | 全員が「じゅんびOK」で自動開始 |
| 描き手拒否 | あり（回答専門で参加できる） |
| 推薦コーナー | 25秒。自分の絵には推薦できない |

## 回答の入力について

原作は「ひらがな以外が混ざると、答えが合っていても不正解」という厳格な仕様で、
公式FAQの筆頭が「ひらがな入力ができません」「回答しても正解になりません」だった。
スマホでそれをそのまま持ち込むと理不尽なので、**入力欄をひらがなに限定したうえで、
判定は表記ゆれに寛容**にしてある。

- 入力欄は打つそばからひらがなに直る（カタカナ→ひらがな、漢字・英数・記号は落とす）。
  IME の変換中は触らないので、日本語入力を壊さない。
- 判定は長音・小書き文字・濁点の揺れを吸収する（`worker/src/kana.js`）。
- 画面には常に「必ずひらがなで入力してください」を出す。
- 入力欄をタップするとキーボードが出て、**キーボード以外をタップすると引っ込む**。
- キーボードが出ている間は `visualViewport` に追従して `--vh` を縮めるので、
  キャンバスが自動的に縮んで入力欄が隠れない。

クライアントとサーバーの正規化は `public/js/kana.js` と `worker/src/kana.js` に
同じ実装がある。**片方だけ変えないこと。**

## 絵の持ち方

ビットマップではなく **作者IDつきのストローク列**で持つ。原作の「荒らしを追放すると
その人の描いた線だけが消える」仕様から読み取った形で、undo・再生・差分同期・
将来の追放機能がこれ1つで解ける。

座標は**キャンバスの幅を 1 とした正規化座標**。x も y も幅で割るので、端末ごとに
画面の縦横比が違っても絵が歪まない。縦横比（`ar` = 高さ/幅）は作品と一緒に保存し、
ギャラリーではその比で再生する。

## ギャラリー・いいね・コメント・シェア

**描かれた絵は、対戦でもソロでも、描いた時点で全部ギャラリーに載る。**
「じぶんの」（`/api/gallery?mine=1`）は自分の作品だけの絞り込み表示。

- **いいね**: `POST /api/drawings/:id/like`（トグル）。ギャラリーの一覧にも
  いいね数・自分がいいね済みかが乗る。
- **コメント**: `GET/POST /api/drawings/:id/comments`。80字まで。
  本文は NFKC をかけない（全角の「！」などを変えないため）。制御文字だけ潰す。
- **シェア**: 絵をクライアント側で PNG にし、Web Share API の files 対応があれば
  画像ごと、なければテキスト+URL、それも無理ならリンクをクリップボードへ、の順に落とす。
  シェアリンクは `/?drawing=<id>`。開くと `GET /api/drawings/:id` で取得して
  その絵の拡大シートをすぐ出す。
- **推薦コーナーとの関係**: 対戦の最後の推薦（1人1票+コメント）は、そのまま
  「その絵へのいいね+コメント」としてギャラリーに残る。審査ではなく賞賛の儀式。

`drawings.posted` / `comments_json` カラムは旧スキーマ（推薦→本人が投稿を選ぶゲート）の
名残で、いまは読み書きしない。既存デプロイの DB を壊さないために残してある。

## 月間絵しりとり

月（JST）ごとに1本のチェーンをみんなで繋ぐ、**非同期・予想型**のしりとり。

- 見えるのは「最後の絵」だけ。**頭文字も、ことばも教えない**。
  「まえの絵はなんだとおもう？」を自分で予想し、**予想の最後の文字**から始まる
  自分のことばを描いて繋ぐ。
- **前の人の実際のことばとの一致はチェックしない**。予想がズレてもしりとりは続く
  （伝言ゲームのように壊れていくのが面白さ）。サーバーが確かめるのは
  「自分の予想と自分のことばがしりとりとして繋がっているか」だけ。
- **ことばが明かされるのは、次の人が繋いだとき**。繋いだ瞬間に答え合わせが出る
  （「せいかい！まえの絵は『◯◯』でした」/「ずれたけど、しりとりはつづく」）。
  だから最後尾のことばは常に伏せられていて、予想のネタバレは起きない。
- 参加すると、その月のチェーン全体が見られる。各エントリに
  「まえの絵を『◯◯』とよんだ（ずれた！）」の注記が付き、どこで壊れたかが分かる。
- ことばはひらがな（入力欄はひらがな限定）。**「ん」で終わることばは不可**
  （「ん」で終わる予想も「前の人は出せないはず」と教える）。
  長音「ー」は飛ばし（「ぎたー」→「た」）、小書きは大書き、濁点・半濁点の揺れは許す。
  判定はサーバー（`worker/src/kana.js`）。
- **同じ人は連続でつなげない**。誰かが更新するのを待つ。
- 同時投稿は楽観ロック。投稿時に「自分が見た最後の番号（prevSeq）」を送り、ズレていたら
  409 で「◯◯さんが先につなぎました」。絵は消えず、新しい絵に予想し直して出せる。
- API: `GET /api/shiritori`（今月の状態。未参加はことば・チェーンが null）
  / `POST /api/shiritori`（`{word, guessedPrev, strokes, ar, prevSeq}`）。

再接続（スマホは通信が切れやすい）は WebSocket が繋ぎ直ったあと、直近に居た部屋へ
自動で再 join する（`app.js` の `lastRoomCode`）。サーバー側は同じユーザーIDの
Player オブジェクトの `ws` を新しいソケットに差し替えるだけで、対戦の進行そのものは
止まらない。
