# わんわん大戦争

オンライン1対1・2レーン型リアルタイム対戦ストラテジー。
仕様は [design/spec.md](design/spec.md)(開発依頼書+システム設計書 2026-07-26 版準拠)を正とする。

- **サーバー権威型**: 戦闘計算・勝敗・報酬はすべてサーバーが確定。クライアントは操作要求のみ送信。
- **データ駆動**: バランス値はコードに直書きせず、管理画面からバージョン単位で編集・テスト・公開・ロールバック。
- ゲームは静的バンドルではなくサーバーを持つため、**GitHub Pages では配信できない**。
  既定のデプロイ先は **Cloudflare Workers + Durable Objects(無料枠で動く)**。
  Google Cloud Run 用の資材も用意してある(手順: [deploy/README.md](deploy/README.md))。
  デプロイ後、その URL をリポジトリ直下の `games.json` に登録するとIZアプリのゲーム一覧に出る。

## 起動方法

```bash
cd games/wanwan/server
npm install
npm start
# → http://localhost:8787 (ゲーム) / http://localhost:8787/admin.html (管理画面)
```

- 環境変数: `PORT`(既定 8787)、`WANWAN_DB`(SQLite パス、既定 server/wanwan.db)、
  `WANWAN_RECEIPT_SECRET`(IZ課金レシートの検証鍵。未設定ならIZ課金は無効)、`FIREBASE_PROJECT`(既定 iz-app-6e1d5)
- **最初に登録したアカウントが管理者**になる(MVP運用。本番では権限付与フローに置き換えること)
- 2クライアント検証はブラウザ2窓(例: `localhost:8787` と `127.0.0.1:8787`)でルームコード対戦が手軽

## テスト

```bash
cd games/wanwan/server
npm test              # ユニットテスト(52件): エンジン/バランス/強化/ガチャ/アビリティ/版ライフサイクル/レシート

```

## 実行環境

同じ `server/src` のコードが、Node でも Cloudflare Workers でも動く。

| | Node(ローカル開発) | Cloudflare Workers + Durable Objects(本番) |
|---|---|---|
| 起動 | `cd server && npm start` | `npm run dev` / `npm run deploy` |
| SQLite | better-sqlite3(ファイル) | Durable Object の SQLite |
| HTTP | express | `worker/express-shim.js`(最小互換) |
| WebSocket | ws | `WebSocketPair` |
| 20Hzループ | setInterval | setInterval(DOが生きている間) |

差し替えは `wrangler.jsonc` の `alias` で行うため、**サーバー側のコードは環境を意識しない**。

## 追加機能(依頼書以降のユーザー要望)

- **試合内レベルアップ**: 対戦中にほねを消費して強化(にゃんこ大戦争の働きネコ相当)。
  ほね容量 / ほね回復 / おうち(メインハウス) / **ペットごとの強化**(必要ほねはペットのコストに比例)。
  **試合ごとにリセット**されるため永続的な強さの差は生じない。コスト・効果量は管理画面で編集可能。
- **図鑑**: ペット・建物・強化の3タブ。各レベルでの数値(HP/攻撃力/ほね上限/1個あたりの秒数/必要ほね)を
  **実際に対戦で使われる公開バランス版の値から算出**して表示する。図鑑は閲覧専用で、
  未所有ペットは「未所有」表示のみ(コインでの個別購入=解放は廃止し、入手はガチャに一本化)。
- **ガチャ**: 新しいペットの入手手段。コインを消費して抽選し、重複時はレアリティごとのコインを還元する。
  抽選・コイン増減・所持付与はすべてサーバーで確定し、結果は `gacha_pulls` に記録される。
  コスト・排出重み・重複還元・10連の確定レアリティ・ペットのレアリティはバランス版のデータ
  (`gacha` / `pets[].rarity`)で、管理画面から編集・公開・ロールバックできる。
- **ランキング**: レート順の上位50位+自分の順位(ホームの「その他」から)。
- **IZ課金**: **1 IZ = 1 コイン(ポイント)**。IZ を消費してゲーム内コインを購入し、ガチャに使える。
  IZ の残高移動は IZ 側サーバー(`purchaseGameCurrency`)のみが行い、ゲームサーバーは
  **HMAC署名済みレシートを検証**して付与する(nonce で二重付与防止)。
  **交換レートはゲーム側の持ち物**で、IZ 側は「IZ をいくら減らすか」しか関知しない。
  レシートが伝えるのは消費した IZ の額(`izAmount`)だけで、付与コインも画面の価格表(購入パック)も
  [src/receipt.js](server/src/receipt.js) の `COINS_PER_IZ` から作る。
  **レート変更はこのリポジトリだけで完結する**(IZ 側の変更・デプロイは不要)。
  環境変数 `WANWAN_RECEIPT_SECRET`(iz 側は Secret `GAME_RECEIPT_SECRET`)に同じ値を設定すること。
- **共通ヘッダー**: ホームと対戦画面**以外**の全画面(たたかう・ルーム・デッキ編成・図鑑・ガチャ・
  ランキング・対戦履歴・設定)に「もどる / タイトル / コイン」のヘッダーを出す。
  **コインをタップするとコイン購入(IZ課金)モーダル**が開く(ホームはプレイヤー情報内のコインが同じ役割)。
  IZアプリ外やIZ未ログインのときは、購入できない理由をモーダル内に表示する。
- **ホーム画面**: ゲーム調のメニュー(デッキ+編集 / たたかう → ランダム・ルーム・CPU / その他)。
- **デザインシステム**([public/style.css](server/public/style.css) 冒頭): モバイルUI/UXの定石に沿って全画面を統一。
  8ptグリッド・48px以上のタッチターゲット・4段階タイポ/2ウェイト・不透明度による階層(100/72/56%)・
  60-30-10配色・黒を使わない着色シャドウ・`env(safe-area-inset-*)` 対応・主要CTAを親指ゾーン配置・
  80msの押下フィードバック。管理画面も同じトークンを使う。

- **IZアカウント自動ログイン**: IZアプリ内(WebView/iframe)で開くと、ホストから `iz:getIdToken` で
  Firebase IDトークンを受け取り、サーバーが署名・aud・iss を検証して自動ログイン(`/api/login-iz`)。
  アカウントは firebase_uid で自動作成・紐付け。単体ブラウザでは従来の表示名+パスワードにフォールバック。
  ※ホスト側(iz-app)の対応が必要: `claude/game-idtoken-bridge` ブランチ(gameBridge.ts / GamePlayScreen.tsx)参照。
- **CPU練習対戦**: 「たたかう」→「CPUマッチ」から1人で練習可能(報酬・レート・対戦記録なし)。
  CPUは設計書§24の方針(防衛優先/ほね8で攻撃/群体に範囲攻撃/高コストの逆レーンを突く)。
  ※依頼書§9でCPU戦は除外範囲だが、マッチング検証・練習用としてユーザー要望により追加。
- **手札の並び固定**: 対戦画面のカードは**デッキ全体をコストの安い順に固定表示**する。
  手札↔控えの入れ替わりで位置が動くと隣のペットを誤爆するため、枠は動かさない。
  クールダウン(残り秒)と控えは枠にマスクを重ねて明示し、ほね不足は淡色化だけで表す
  (ほねは数秒ごとに増減するため、文字マスクを出すと点滅してわんこの絵が隠れる)。
  クールダウン中・控えのペットも強化できる(強化は元々デッキ全体が対象)。
- **対戦画面のカメラ**: 既定で自陣側にズームイン(視界=フィールドの約1/3)。ホイール/ピンチでズーム、
  ドラッグでパン、ダブルクリックで既定位置へ。「マップ」ボタンで全体表示(表示中は操作不可)。
- **施設・遠距離攻撃の弾道表示**: どこから攻撃されたか分かるよう発射元から着弾まで弾を描画。

## 管理画面(`/admin.html`)

6タブ構成。非開発者がバランス調整と日々の運用を完結できることを目標にしている。

| タブ | できること |
|---|---|
| バランス | 版の一覧/作成/複製/ラベル/削除、**全パラメータの編集**(ルール・施設・進行・マッチング・ガチャ・強化)、**ペットの追加/複製/削除と全項目編集**、**アビリティのGUI編集**(型はカタログから選択、範囲検証つき)、検証、**任意の2版の差分**、テスト反映、**公開予約**、公開、ロールバック、**JSONの入出力** |
| アカウント | 名前/ID/firebase_uid 検索・状態/並び替え、**ユーザー詳細**(所持ペット・デッキ・対戦履歴・ガチャ履歴・課金履歴)、コイン/XP/レート/レベルの増減、ペットの付与・剥奪、停止/再開(停止は即ログアウト)、**管理者権限の付与・剥奪**(最後の1人は剥奪不可) |
| 試合 | 期間・版・結果・ユーザーで検索し、**イベントのタイムライン**まで確認 |
| 分析 | 期間+バランス版で絞り込み。KPI(新規/アクティブ/試合数/平均試合時間/切断)、試合数推移、**決着理由**、レート分布、ペット採用率・勝率、**ガチャの実績排出率と理論値の乖離**、IZ課金の売上 |
| 稼働 | 進行中の試合・接続状況・マッチング待機列を5秒ごとに更新 |
| 監査 | 操作/実行者/期間/フリーワードで検索、追加読み込み、CSV出力 |

- **公開予約**: 予約した版はサーバーが30秒ごとに確認して自動公開する(進行中の試合は開始時の版のまま=VERSION-01)。
- **理由の必須化**: 公開・ロールバック・予約・削除・付与・停止・権限変更は理由なしでは実行できず、監査ログに残る。
- **アビリティ**: [src/abilities.js](server/src/abilities.js) のカタログが唯一の入口。`engine.js` に実装のない型は
  カタログに置けない(ユニットテストで機械的に検査)。保存時にパラメータの範囲も検証する。

## 実装済みの受入基準

ACC-01(初期4体+初期デッキ) / DECK-01(4〜8体・重複/未所有拒否) / MATCH-01(オンラインマッチ・ルームコード) /
BATTLE-01(サーバー判定の出撃〜施設攻撃) / BATTLE-02(延長・即時勝利・タイブレーク・引き分け) /
HAND-01(4〜8体デッキの手札循環+個別CD) / NET-01(再接続で完全スナップショット復帰) /
NET-02(不正出撃・連番重複の拒否) / ADMIN-01/02(下書き→検証→テスト→公開→ロールバック) /
VERSION-01(試合中の公開は既存試合に影響しない) / LOG-01(対戦履歴・イベント・監査ログ) /
REWARD-01(XP・コイン・レートの冪等更新) / OPS-01(管理画面から安全に公開) /
GACHA-01(サーバー抽選・排出率公開・重複還元・所持付与・履歴記録) /
ADMIN-03(アビリティのGUI編集と検証) / ADMIN-04(危険操作の理由必須) / ADMIN-05(入出力・削除・ラベル) /
ADMIN-06〜09(アカウント検索・詳細・付与/剥奪・権限・停止) / ADMIN-10〜13(試合調査・分析・稼働・監査)

## 未対応(仕様上の除外・将来対応)

- 必殺技「おやつタイム」(設計書 §13 で要確定 → 初期対象外を選択)
- サウンド(素材未制作。`assets/` に追加後クライアントへ組み込み)
- テスター限定環境(testing 版で実際にマッチングする仕組み)、負荷試験
- 管理画面の多要素認証・IP制限(現状は通常のセッション+管理者フラグのみ)
- スケールアウト(単一Nodeプロセス+SQLite前提。複数インスタンス化にはルーム分散とDB外部化が必要)

## 素材生成パイプライン(tools/)

- 静止画: Vertex AI `gemini-3.1-flash-image`(ADC認証)/ 動画: `veo-3.0-fast-generate-001`
- ペットは idle を静止画生成 → Veo image-to-video で walk/attack/hitfall を動画化 → ffmpeg でフレーム抽出
- 白背景は外周フラッドフィルで透過化(白い被写体に穴が開かない)
- 施設の敵チームカラー(赤)は青系ピクセルの色相回転で機械生成

```bash
cd games/wanwan/tools
npm install
gcloud auth application-default login
node generate-assets.js   # 生成済みはスキップ。FORCE=true ONLY=<id> で個別再生成
```
