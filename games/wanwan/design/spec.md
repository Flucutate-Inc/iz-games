# わんわん大戦争 — 実装仕様書 v2

> 本書は 2026-07-26 受領の「開発依頼書」([development-request.txt](development-request.txt))および
> 「ゲーム・システム設計書」([system-design.txt](system-design.txt))を正とする実装仕様。
> 旧仕様書(v1: フロントのみ・同一端末/CPU対戦前提)は破棄した。

## 0. 最重要方針(設計書 §1)

- **オンライン1対1のみ**。CPU戦・ステージ攻略・ガチャ・課金は対象外。
- **戦闘結果はサーバーを正**とし、クライアントは操作要求のみ送信する。
- **バランス値をコードに直書きしない**。管理画面からバージョン単位で編集・テスト・公開・ロールバックできる。
- マッチ成立時にバランスバージョンIDを固定し、試合途中に数値が変わらない。

## 1. ゲームルール

| 項目 | 初期仕様 |
|---|---|
| 試合時間 | 通常180秒 + 延長60秒(延長中ほね回復2倍) |
| レーン | 上・下2本。通常ペットはレーン移動しない |
| 施設 | 各レーンハウス(HP8,000/攻180/射程230/1.2s) + メインハウス(HP12,000/攻250/射程250/1.0s、自軍レーンハウス破壊後に起動) |
| ほね | 開始4 / 最大10 / 2.5秒に1回復。不足時は出撃不可(予約なし) |
| 勝利 | メインハウス破壊で即時勝利。時間切れは 破壊レーンハウス数→施設総ダメージ→メインハウス残HP率→引き分け |
| 攻撃順 | 敵ペット → レーンハウス → メインハウス |

## 2. アカウント・進行

- アカウント: 一意ID、表示名、レベル、経験値、コイン、レーティング、勝敗数、対戦履歴。
- **初期付与4体**: まめ柴・ブルドッグ・ダックスナイパー・ポメラニアン軍団(+初期4体デッキ)。
- ペット入手: **ガチャのみ**(§2.1)。コインでの個別購入=「解放」は廃止した。**敗北時もXP・コイン付与**。
- 未所有ペットも図鑑で性能を確認可能(図鑑は閲覧専用)。性能レベル差はなし(所有可否とデッキ構築のみが影響)。

### 2.1 ガチャ(依頼書以降のユーザー要望・解放の置き換え)

- コインを消費して抽選する。1回引き / まとめ引き(既定10連)の2種。
- ペットは **レアリティ**(既定 N / R / SR)を持ち、レアリティ重みで抽選 → そのレアリティ内から均等抽選。
- すでに所持しているペットが出た場合は **重複** としてレアリティごとのコインを還元する
  (同じ抽選の中で2回出た場合も2回目は重複)。
- まとめ引きは `multiGuaranteeRarity` 以上を1回以上保証する。
- 抽選・コイン増減・所持付与はすべてサーバーで確定し、`gacha_pulls` に記録する(LOG-01)。
- コスト・排出重み・重複還元・確定レアリティ・各ペットのレアリティは
  バランス版のデータ(`gacha` / `pets[].rarity`)。管理画面から編集・検証・公開・ロールバックできる。
- 排出率はクライアントに開示する(合計100%になるよう正規化して表示)。

## 3. デッキ・手札(v1からの変更点)

- デッキは所有ペットから **4〜8体**(重複不可)。
- 手札は最大4体。デッキ4体なら4体全て表示。
- 使用したペットは**個別クールダウン**状態へ → CD終了後に手札へ直接復帰。控え(手札ローテーション)は廃止し、デッキ全ペットが常時手札に並ぶ。

## 4. オンライン対戦設計

- 通信: WebSocket。サーバーロジック 20〜30Hz、状態差分 10〜20Hz、フルスナップショット1〜2秒ごと、クライアントは補間描画。
- クライアント送信: 出撃(petId+レーン)/降参/再接続要求。すべてサーバーで検証(所有・手札・ほね・上限・連番・重複)。
- 切断: サーバー上の試合は継続。再接続猶予10秒・切断敗北30秒(ルールで可変)。再接続時は完全スナップショット返却。サーバー障害は無効試合(報酬・レート変更なし)。
- マッチング: レーティング主軸、待機時間で許容差拡大、初心者保護、同一相手連続抑制。ランダムマッチ+ルームコード対戦。

## 5. 管理画面・バランス管理

- 管理対象: ペット全戦闘値 / アビリティ / 試合ルール / 施設 / 進行(初期配布・XP・コイン) / ガチャ(コスト・排出重み・重複還元・レアリティ) / マッチング / 運用。
- バージョンライフサイクル: `draft → testing → scheduled → published → archived / rolled_back`。
  - 現行版を複製して下書き → 編集・バリデーション → テスト反映 → 本番公開(不変スナップショット) → 問題時ロールバック。
  - `scheduled` はサーバーが30秒ごとに確認して自動公開する(公開後は新規マッチにのみ適用)。
  - 下書きは削除可能、任意のスナップショットをJSONで入出力できる(バックアップ・環境間移送)。
- アビリティは「トリガー+条件+対象+効果+制限」のデータ組み合わせ。特殊挙動はサーバー実装済みハンドラーを選択。
  カタログ([server/src/abilities.js](../server/src/abilities.js))に定義された型のみ選択でき、
  型・パラメータ範囲は保存時に検証する。**カタログの型は engine.js の実装と1対1**(テストで担保)。
- ペットは管理画面から追加・複製・削除でき、全戦闘値・分類・テキスト・アビリティを編集できる。
- 安全機能: 入力範囲検証、DPS/HP効率警告、任意2版の差分表示、未保存の警告、全操作の監査ログ(検索・CSV)、
  権限分離(管理者権限の付与/剥奪。最後の1人は剥奪不可)、**危険操作の理由必須**。
- 運用・分析: アカウント検索/詳細/付与・剥奪/停止、試合のイベント調査、
  KPI・ペット・ガチャ(実績と理論排出率の乖離)・売上を期間とバランス版で絞り込み、稼働状況の監視。

## 6. データ設計(主要テーブル)

`users / pets / user_pets / decks(+内容) / matches / match_events / gacha_pulls / balance_versions / (版ごとの) pet・ability・battle_rules・facility 定義 / audit_log`

公開時にバランス一式を不変JSONスナップショット化。ゲームサーバーはロード完了後の新規マッチにのみ適用。

## 7. 画面

タイトル/認証、ホーム、ペット一覧・図鑑、ガチャ、デッキ編成、マッチング、対戦、リザルト、対戦履歴、設定、管理画面。

| 項目 | 決定 | 根拠 |

| クライアント | Web(ブラウザ)、vanilla JS + canvas | 依頼書は未確定。既存素材・リポジトリ構成と親和 |

| ルームコード対戦 | ランダムマッチと両方実装 | 依頼書 §10 の要確定事項 → 両対応 |
| デプロイ | ローカル/任意のNodeホスティング(Cloud Run等)。手順は server/README | インフラ未確定のため |
